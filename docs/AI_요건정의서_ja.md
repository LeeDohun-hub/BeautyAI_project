# BeautyAI 要件定義書

> 韓国語版: [AI_요건정의서.md](./AI_요건정의서.md)

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| システム名 | BeautyAI（サービス名 **YoPalette**） |
| 対象 | 写真1枚で肌・パーソナルカラー・ネイルを分析し、商品を推薦するサービス |
| 目的 | 分析結果を根拠として購入可能な商品までつなぎ、その結果を BeautyWEB のアカウント・カートへ引き渡す。 |
| 作成基準 | 2026-08-10 時点の実装コード |
| 前版 | 2026-06-29。当時は顔・体の肌分析と推薦・相談のみだった。**パーソナルカラー・ネイル・バーチャル整形・多言語・Web連携が追加されたため全面改訂する。** |

## 2. サービス範囲

BeautyAI は5つの独立したモジュールで構成される。

| モジュール | 内容 |
|---|---|
| ホーム | モジュール選択、Webアカウント連携状態の表示 |
| 肌ケア分析 | 顔・体の写真分析 → 成分・商品推薦 → 結果シート |
| パーソナルカラー | 顔写真 → シーズン判定 → パレット・メイク → アイテムマッチング → 結果シート |
| ネイル・ペディ | 手足の写真 → ネイル検出・発色プレビュー → 類似デザイン・商品 |
| バーチャル整形 | 顔の比率分析 → 目標別プレビュー → 相談用レポート |

## 3. 利用者

| 利用者 | 説明 | 主な行動 |
|---|---|---|
| 匿名利用者 | ログインせずに利用 | アンケート → 写真分析 → 推薦確認 |
| Web連携利用者 | BeautyWEB アカウントで入ってきた利用者 | プロフィール事前入力、保存済みパーソナルカラーの利用、結果シートQR → Webカート |
| 日本語利用者 | 画面言語を日本語で使う利用者 | 上記と同じ。**すべての案内・判定文が日本語であること** |
| 運営者 | サービス指標を見る利用者 | 統計の照会 |

## 4. 機能要件

### 4.1 アンケート

- 年齢・性別・人種・肌タイプ・敏感度・お悩みを受け取る。
- 個人情報利用の同意前は次のステップに進めない。
- Webアカウントで入ってきた場合はプロフィールでアンケートを事前入力する。

### 4.2 顔の肌分析

- 写真1枚以上で6項目（トラブル・毛穴・シワ・赤み・色素沈着・皮脂）を0〜100で算出する。
- 撮影品質に応じた信頼度の案内を併せて出す（顔が未検出・照明など）。
- 複数枚を入れると平均でブレを抑える。
- ⚠ 6項目は互いに完全には独立しない。**3グループ・3区分表示**を原則とし、小数点まで断定的に見せない。

### 4.3 体・皮膚疾患スクリーニング

- 体の写真から皮膚疾患の可能性をスクリーニングする（確定診断ではないことを必ず明示）。
- 悪性の疑いは商品推薦ではなく受診の案内を優先する。
- 刺激の可能性がある成分（レチノール・AHA/BHA）は除外する。

### 4.4 乳幼児

- 乳幼児は大人向け製品にフォールバックしない。**成分優先の案内**に置き換える。
- 香料のゲートは多言語で検査する。日本語の香り表現が抜けると、子どもに香料が漏れる。

### 4.5 パーソナルカラー

- 顔写真からシーズンタイプを判定し、判定根拠・境界の案内を出す。
- パレット・メイクカラー・スタイルムードを提示する。
- Webに保存されたパーソナルカラーがあれば、撮影なしで利用できる。
  - このとき `metrics` が空になるため、**撮影品質バッジを隠す**（0%と表示されると誤解を与える）。
- 顔型分析も併せて提供する。

### 4.6 アイテムマッチング（商品推薦）

- 判定結果に合う商品を**カテゴリ列**で表示する。

| 対象 | 列 |
|---|---|
| パーソナルカラー（女性） | リップ・チーク・アイ・ベース・ネイル |
| パーソナルカラー（男性） | ベース・アイブロウ・コンシーラー・リップバーム |
| 肌（顔） | クレンザー・化粧水・美容液・保湿・日焼け止め |
| 肌（体） | ボディウォッシュ・ボディ保湿 |

- 地域（韓国/日本）と購入プラットフォーム（オリーブヤング・Amazon・楽天・マツキヨなど）で絞り込める。
- 購入リンクのないカードは出さない。
- 価格は表示しない。1枚のカードに販売先が複数あるため、どの値を使っても最低1つは誤りになる。

### 4.7 ネイル・ペディ

- 手足の写真からネイル領域を検出し、色を抽出する。
- 選んだ色で発色プレビューを作る（楕円近似のため実際と異なり得ることを明示）。
- 類似デザインを検索し、その色で購入できる商品を表示する。

### 4.8 バーチャル整形

- 顔の比率を分析し、目標別（卵型・Vライン・童顔など）のプレビューを作る。
- シミ・ほくろは自動除去ではなく、**利用者が選んだ位置のみ**処理する。
- 結果は相談用レポートであり、手術結果の予測ではないことを明示する。

### 4.9 AI相談

- 肌のお悩み・成分・ルーティンの質問に答える。
- 根拠がある場合は参考根拠を併せて表示する。
- カタログに関する質問は **LLM ではなく DB が**答える。

| 質問の種類 | 処理 |
|---|---|
| 「〇〇という商品はありますか？」 | カタログ照会。無ければ無いと答える（作り話をしない） |
| 「店舗に無いと言われました。他のおすすめは？」 | 在庫を知っているふりをせず、肌スコアに基づく同じ成分系統の商品を提示 |
| その他の相談 | 根拠を検索したうえで LLM が回答を作成。失敗したら知識ベースへフォールバック |

- 回答を作成中であることを画面に文字で伝える。
- 範囲外の質問には無理に答えない。

### 4.10 結果シート

- 分析結果と選んだ商品を印刷用の結果シートにする。
- 結果シートQRで BeautyWEB のカートに追加できる。

### 4.11 Web連携

| 方向 | 要件 |
|---|---|
| WEB → AI | 120秒・使い捨てのハンドオフチケットでログインする。アクセストークンをそのまま受け取らない。AI独自セッションは12時間。 |
| AI → WEB | 結果シートQRには使い捨てコードのみを載せる。商品リストはサーバー間でやり取りする。 |

### 4.12 多言語（韓国語 / 日本語）

- 画面の文言はフロントの辞書で置き換える。
- **数値・名前が差し込まれて組み立てられる文**（判定文・要約文・相談回答）はフロント辞書では置き換えられないため、**サーバーが韓国語・日本語の2種類を作って返す**。
- 翻訳が無ければその段落を省略する。日本語画面に韓国語を混ぜない。

### 4.13 個人情報

- 自分のデータ（分析・アンケート・推薦・相談履歴）の削除機能を提供する。
- アップロードしたファイル名は保存しない（拡張子のみ残す）。

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| 応答時間 | 顔の推薦は CPU推論 + ライブ検索が重なっても実用範囲を保つ。成分インデックスはキャッシュし、ランキングのループで関連のロードを行わない。 |
| レスポンシブ | 360px（Galaxy）で商品推薦が1画面に複数表示され、どのカテゴリかが常に分かること。 |
| アクセシビリティ | タッチ端末でボタン・チップのタップターゲット下限44pxを守る。色は補助的な手がかりであり、名札は常に文字で残す。 |
| 安全性 | 分析結果は参考であり確定診断ではないことを画面に明示する。悪性の疑いは受診を優先案内する。 |
| データ | モデルファイル・RAGコーパスが無ければ該当機能は `feature_available=false` でオフになる。サービス全体が落ちない。 |
| 再現性 | 組み立て型の韓国語文はリストで固定し、新たに増えたらテストが検知する。 |

## 6. 外部連携

| 対象 | 用途 | 備考 |
|---|---|---|
| BeautyWEB | アカウントのハンドオフ、カート追加、カタログ供給 | `JWT_SECRET` を共有 |
| OpenAI | 相談回答の生成 | キーが無ければ知識ベースへフォールバック |
| 楽天API | 日本の商品検索 | 呼び出し頻度制限に注意 |
| オリーブヤング | 商品カタログ | 国内モールはボット遮断があるためブラウザ経由で収集 |
| Amazon | 商品リンク | 検証済みのASIN直リンクのみ使用 |

## 7. 対象外

- 医学的な診断・処方
- 実際の決済（BeautyWEB が担当）
- 施術・手術結果の保証
- 利用者写真の外部共有

## 8. 用語

| 用語 | 意味 |
|---|---|
| アイテムマッチング | 判定結果に合う商品をカテゴリ列で提示する機能 |
| 結果シート | 分析結果と選んだ商品を載せた印刷用シート |
| ハンドオフチケット | WEBアカウントを AI へ引き渡す120秒・使い捨てトークン |
| 組み立て型の文 | 数値・名前が差し込まれ、完成形が毎回変わる文。サーバーが言語ごとに2種類作る |
