# BeautyAI System Design Overview（日本語版）

> 韓国語版: [AI_system-design-overview.md](./AI_system-design-overview.md)

## 1. 目的

BeautyAI（YoPalette）のランタイム構成、リクエスト経路、処理フローを1枚で把握する。詳細は `AI_기본설계서_ja.md` / `AI_상세설계서_ja.md` / `AI_ERD_ja.md` を参照。

- 作成基準: 2026-08-10、実装コード

## 2. アーキテクチャ

```
                         インターネット
                            │ 443
                  ┌─────────▼──────────┐
                  │ Caddy 2            │  ai.yopalette.com
                  │ 自動HTTPS           │  ※ 80番は証明書更新に必要 — 閉じないこと
                  └─────────┬──────────┘
                  ┌─────────▼──────────┐
                  │ frontend           │  nginx + React 18 + MUI
                  │（コンテナ内部 8080） │  /api, /internal → backend:8000
                  └─────────┬──────────┘  ※ ホストポートを公開しない
                  ┌─────────▼──────────┐
                  │ backend :8000      │  FastAPI
                  │  ├ api/routes      │
                  │  ├ services (37)   │
                  │  └ ai（モデルローダ）│
                  └───┬────────────┬───┘
          ┌───────────▼──┐    ┌────▼──────────────┐
          │ PostgreSQL   │    │ /data（ボリューム） │
          │ 11テーブル     │    │  models/*.pt      │
          └──────────────┘    │  rag/*.jsonl      │
                              │  カタログ           │
                              └───────────────────┘

  外部 ── BeautyWEB（アカウントチケット・カート・カタログ）
        ── OpenAI（相談の生成）
        ── 楽天 / オリーブヤング / Amazon / マツキヨ（商品・リンク）
```

重要な性質。

1. **外部との接点は Caddy ひとつ。** フロントはホストポートを公開しない。
2. **APIのルーティングはフロントの nginx が行う。** Caddy はホストを振り分けるだけ。
3. **`/data` が無ければモデルも無い。** コンテナ基準のパスは `/data` であり `/app/data` ではない。マウントがずれると機能が静かにオフになる。

## 4. 処理フロー

### 4.1 顔の肌分析

```
写真アップロード
  → 顔検出（MediaPipe） → 余白を持たせたクロップ
  → 肌ピクセルのマスキング（ホワイトバランス補正を先に）
  → モデル推論6項目 + 赤みは LAB a* の実測値で置換
  → 撮影品質の信頼度の案内（ko/ja の2種類）
  → skin_analyses に保存
```
複数枚を入れると平均を取る。照明の差が最大の誤差要因であり、平均が最も効く改善レバーである。

### 4.2 推薦

```
スコア + アンケート
  → 優先お悩み集合 → 成分の上位5件
  → ルーティンスロット別の候補収集（成分インデックスはキャッシュを使用）
  → プラットフォームリンク付与 → リンクが空のカードを除去
  → 要約文（explanation、改行を含む） + 成分の根拠（evidence）を分離
  → recommendation_histories に保存
```

### 4.3 パーソナルカラー → アイテムマッチング

```
写真 → Lab回帰 → 季節ルール → シーズン・トーン判定（+判定根拠・境界の案内）
   │
   └─ Webに保存されたパーソナルカラーがあれば撮影をスキップできる
        （このとき metrics が空になるため撮影品質バッジを隠す）
   ▼
カテゴリ別の色キーワード → ライブ検索 + ローカルカタログ
   → resolve（リンク付与） → balance（列のバランス） → 画面
```
⚠ resolve が balance より**先**でなければならない。戻すと一部の列が丸ごと空く。

### 4.4 相談

```
質問
 ├─ カタログの質問？ → DB照会で回答（LLMを経由しない）
 ├─ LLMが使えるか？  → 根拠を検索 → LLM が文を作成 → 出典を表示
 └─ フォールバック   → 問題肌コーパス → 成分コーパス → キーワード → 範囲外の案内
```
知識検索は関連度が同程度であれば、**利用者と属性が同じ事例**を優先する。コーパスの回答が事例の原文であり、最初の文がその事例本人の年齢・性別で始まるためである。

### 4.5 Web連携

```
WEB → AI :  #t=<120秒・使い捨てチケット> → POST /api/auth/exchange → AIセッション（12h）
            ※ 消し込んだ jti は used_tickets に残して再利用を防ぐ

AI → WEB :  結果シートQR = <WEB>/cart?ai=<code>
            WEB → POST /internal/cart-handoff/resolve → 商品リストを回収
            ※ QRにリストは載せない（1KBを超えると認識率が落ちる）
```

## 5. モジュールの責務

| モジュール | 責務 | やらないこと |
|---|---|---|
| `ai/` | チェックポイントのロード・推論 | ビジネス判断 |
| `services/*_analyzer` | 写真 → 数値・判定 | 商品の選択 |
| `services/recommender` | 成分・商品・列・要約文 | モデル推論 |
| `services/*_knowledge` | 根拠検索・文の組み立て | 回答生成（LLM） |
| `services/chatbot` | 回答経路の決定 | カタログの事実判断 |
| `services/chat_catalog_answers` | カタログの事実回答 | 相談・成分の助言 |
| `services/platform_*` | 購入リンクの解決・可用性 | 価格の表示 |
| `api/routes` | HTTPの境界 | ドメインロジック |

## 6. データ保存の方針

| データ | 保存 | 方針 |
|---|---|---|
| アップロード写真 | 保存しない | 拡張子のみ記録（ファイル名に個人情報が入りやすい） |
| 分析スコア | `skin_analyses` | 利用者の要求で削除 |
| アンケート | `surveys` | 同上 |
| 推薦・相談履歴 | `recommendation_histories`, `chat_histories` | 同上 |
| ハンドオフコード | `cart_handoffs` | 短い有効期限 + 使い捨て |
| 消し込みチケット | `used_tickets` | jti のみ保持 |

`DELETE /api/me/data` で利用者が自分で削除できる。

## 7. 品質基準

| 項目 | 基準 |
|---|---|
| 応答時間 | 推薦は成分インデックスのキャッシュでリクエストあたり数秒を削る。ランキングのループで関連ロードは禁止。 |
| プロキシのタイムアウト | CPU推論 + ライブ検索が重なるため300s。フロントの nginx と Caddy の値を揃える（短い方が先に切る）。 |
| モバイル | 360px で商品推薦が2列で表示され、スクロール中もカテゴリヘッダーが固定される。横はみ出しなし。 |
| アクセシビリティ | タッチのタップターゲット下限44px。ヘッダー色の上の文字コントラスト4.5:1以上。 |
| 多言語 | 日本語レスポンスに韓国語が残らない（テストで強制）。 |
| 安全 | 確定診断ではないことを明示。悪性の疑いは受診を優先。乳幼児は大人向け製品へのフォールバック禁止。 |

## 8. 既知の制約

- 肌6項目の回帰は項目間の分離度が低い。3グループ・3区分の表示で緩和する。
- 発色プレビューは楕円近似である。実際の発色と異なり得ることを画面に明示する。
- `redis` は設定にのみ存在し、コードは使っていない。使い捨てチケットはDBのユニーク制約で処理する。
- 商品価格は表示しない（販売先が複数あり、どの値も一致しない）。
- CI環境には `data/` が無いため、データ依存のテストには skip ガードが必要である。
