# 매니페디큐어(네일 디자인 이미지분석) 기능 설계

작성 2026-07-27 · 상태: **설계(구축 전, 데이터 블로커 있음)**

홈 '추후 추가' 카드([App.tsx:1622](../frontend/src/App.tsx#L1622))를 진입점으로 하는 네일/페디 디자인 분석 모듈의 설계. 퍼스널컬러의 네일 '색상' 추천(이미 5번째 카테고리로 동작 중)과 **별개 트랙**으로, 손/발 사진에서 네일 디자인을 분석·추천하는 이미지분석 기능.

## 0. 지금 당장의 블로커 (선결 과제)

> **2026-07-28 갱신 — 블로커 일부 해소.** 공개 소스(CC BY 4.0)로 우회 경로를 확보했다:
> 사전학습 YOLOv8 네일 세그 모델로 **학습 없이 네일 마스크**를 얻고(보유 발 909장 100% 검출),
> Roboflow 손톱 7,025장으로 **손 트랙 0바이트를 대체**했다. → **B안 리트리벌 MVP는 지금 착수 가능.**
> 남은 블로커는 **범주 라벨**(A안 분류)뿐이며, 이는 AI-Hub 04 메타데이터 확보가 여전히 필요하다.
> 상세: [nail_alternative_data_report_20260728.md](nail_alternative_data_report_20260728.md)

`data/04.네일 및 페디큐어 데이터` 는 **불완전 다운로드** 상태라 현재 학습 불가:

| 구분 | 원천(이미지) | 라벨 |
|------|-------------|------|
| 발 Training | TS_발 284MB ✅ | TL_발 **0 bytes ❌** |
| 발 Validation | VS_발 32MB ✅ | VL_발 11MB(텍스처 PNG) |
| 손(hand) 전부 | **0 bytes ❌** | **0 bytes ❌** |

- **범주형 클래스 라벨(JSON/CSV)이 전혀 없음.** 데이터 포맷은 `D{디자인ID}_02_RGB_01.png`(원천 사진) + `D{디자인ID}_02_Texture_{영역}_{변형}.png`(디자인 텍스처 크롭, 디자인당 ~18개). → 단순 분류가 아니라 **세그멘테이션/디자인-텍스처 매칭** 계열.
- AI-Hub **구축 가이드/주석 스펙 문서 부재** → 텍스처·RGB의 정확한 의미, 의도된 태스크 미확정.

**선결(사용자/데이터 담당):**
1. AI-Hub 04 "네일 및 페디큐어 데이터" **전량 재다운로드**(손+발, Training 원천+라벨, Validation 포함).
2. 데이터셋 **구축 가이드(주석 스펙)** 확보 — 텍스처 라벨의 의미와 의도된 태스크(세그멘테이션? 디자인 분류? 리트리벌?) 확정.
3. 확보 후 아래 §3 데이터 파이프라인부터 실행.

> 데이터가 이 형태(텍스처 크롭, 범주 라벨 없음)로 확정되면, MVP는 **학습 없는 리트리벌(디자인 검색)** 로 시작하는 것을 권장(§2-B). 분류/세그멘테이션 학습은 라벨 확보 후 2단계.

---

## 1. 태스크 정의 (데이터 형태에 맞춘 3안)

- **A. 디자인 분류(Classification)** — 사진 → 디자인 카테고리(프렌치/글리터/그라데이션/아트 등). *전제: 범주 라벨 필요(현재 없음).* 라벨 확보 시 채택.
- **B. 디자인 리트리벌(Retrieval, MVP 권장)** — 사진에서 네일 영역 크롭 → 임베딩(사전학습 CNN/CLIP) → 텍스처 라이브러리(VL_발의 1,864 텍스처)와 최근접 검색 → "비슷한 디자인 + 재현용 상품(젤/폴리시)" 추천. *학습 불필요, 현재 텍스처 데이터만으로 가능.*
- **C. 네일 세그멘테이션 + 디자인 오버레이** — 네일 마스크 검출 후 디자인 텍스처를 합성 미리보기(가상 네일). *가장 무겁고 라벨/마스크 필요.*

권장 로드맵: **B(MVP) → 라벨 확보 시 A → 여력 시 C**.

## 2. 파이프라인 (기존 자산 재사용)

- 네일 영역 검출: 기존 얼굴/바디 파이프라인의 mediapipe/detection 자산 재사용 검토(손/발 랜드마크).
- 임베딩·리트리벌: 사전학습 백본(다운로드 금지 환경 고려 — 이미 받은 모델 우선). RunPod 학습 번들 방식은 [aihub03-skin-classifier-retrain] 선례 따름.
- 추천 연결: 검출된 디자인 → 재현 상품(젤/폴리시/네일아트)은 **item-match nail 카테고리 라이브검색 재활용**([pc-item-match-pipeline] — nail 컬럼, oy/amazon/라쿠텐 직링크). 핸드/풋 케어 상품은 카탈로그의 예약된 `hand.*`/`foot.*` 활용([body_categories.py](../backend/app/services/body_categories.py)).

## 3. 데이터 파이프라인 (데이터 확보 후 착수)

1. 04 zip 추출 → `scripts/build_nail_design_dataset.py`(신규)로 `data/manifests/nail_design.csv` 생성: 디자인ID, 부위(손/발), RGB 경로, 텍스처 경로들, (라벨 확보 시) 카테고리.
2. 무결성 검증(스킨/PC 트랙 선례): 손·발 균형, 디자인당 텍스처 수, 이미지 CRC.
3. (B안) 텍스처 임베딩 인덱스 사전계산 → 서빙 시 최근접 검색.

## 4. 백엔드 API (신규)

- `POST /api/analyze-nail-design` (multipart 이미지 + region) → `{ region, detected_designs:[{design_id, similarity, thumbnail}], recommendations:{ nail: [ProductOut], hand_foot_care: [ProductOut] } }`.
- 안전/일관성: 얼굴·바디·PC와 동일하게 이미지 검증·에러 처리, 직링크만 노출 정책 유지.

## 5. 프론트 (홈 카드 활성화)

- 홈 '추후 추가' 카드 → "네일·페디 디자인" 모듈로 교체(비활성 → 활성, ImagePlus 아이콘 유지). 진입 시 손/발 사진 업로드 → 결과: 유사 디자인 캐러셀 + 재현 상품(네일 컬럼) + 핸드/풋 케어.
- 결과 카드/버튼 체계는 기존 item-match 카드 재사용(플랫폼 버튼·이미지 규칙 동일: **올리브영 이미지 미사용**, 직링크 있으면 표시).

## 6. 단계별 계획

1. **[블로커]** 04 전량 재다운로드 + 구축 가이드 확보.
2. 데이터 파이프라인(§3-1,2) + 데이터 실태 리포트.
3. MVP: B안 리트리벌 + `/api/analyze-nail-design` + 홈 카드 활성화(손/발 중 데이터 있는 쪽부터).
4. 라벨 확보 시 A안 분류 학습(RunPod 번들), eval 비교 후 교체.
5. (선택) C안 세그멘테이션·가상 네일 미리보기.

- 진입점을 홈 전용 카드로 둘지, PC 결과 안에 '디자인' 섹션으로 붙일지.
